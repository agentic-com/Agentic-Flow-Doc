:::note[In 20 seconds]
An expression is text between double curly braces, like `{{ $input.title }}`, that AWFlow replaces with a value while the node runs. It runs once for every item, so the same setting can produce a different value for each one. Use `$input` for the incoming item, `$('Step name')` for another step, `$vars` for your [variables](/app/variables/), and `$run` for a value set earlier in the run.
:::

## See it happen

Edit Fields receives two orders and builds two fields from expressions. Each expression is worked out once per item.

## What you can read

| Write | Reads | Example |
| --- | --- | --- |
| `$input` | The item this step is working on | `{{ $input.title }}`, `{{ $input.metadata.description }}`, `{{ $input.items[0].name }}` |
| `$('Step name')` | The output of another step, by its name | `{{ $('Get Page Metadata').title }}` |
| `$vars` | A [variable](/app/variables/) you set on the Variables page | `{{ $vars.BASE_URL }}` |
| `$run` | A value stored earlier in this run by [Set Variable](/nodes/builtin/flow/setvariable/) | `{{ $run.cursor }}` |
| `$now`, `$today` | The date and time the step started, today's date | `{{ $today }}` |
| `$itemIndex` | Which item the step is working on, from 0 | `{{ $itemIndex + 1 }}` |
| `$execution`, `$workflow` | This run (`id`, `mode`) and this workflow (`id`, `name`) | `{{ $workflow.name }}` |

- **Paths** use dots, or brackets for names with spaces, dashes, dots or symbols: `$input["First name"]`, `$input.rows[0]["Order #"]`. Counting starts at 0: `$input.items.0.name` and `$input.items[0].name` are the same.
- **Step names** go in single or double quotes: `$('Get todos')` or `$("Bob's sheet")`. They must match the step's name exactly. When two steps share a name, the run log warns you and the first one is used: give them different names.
- Only the data's **own fields** are read: `$input.constructor` or `$input.__proto__` give nothing.
- **`$('…')` and items:** a step directly before this one gives the matching item; `.all()`, `.first()` and `.last()` read its whole list. See [Item linking](/concepts/data/item-linking/).
- **`$vars` and `$run` are strict:** reading a variable nobody set **fails the step** with an error that names it, never an empty value. `$vars` values are read once when the run starts.

You rarely type `$input` yourself: tap a value in the **Input** pane or in **Use data**, or drag it, and the expression is written for you. See [Mapping in the UI](/concepts/data/data-mapping/data-mapping-ui/).

## Typing an expression

A field is either **Fixed** (the text is used as written) or **Expression**. Switch with the field's **⋯** menu (**Edit as expression** / **Use a fixed value**), or the **Fixed | Expression** switch next to the label on a wide screen.

- Typing `{{` adds the closing `}}` with the cursor in between; typing `}` steps over it.
- Inside `{{ }}`, **suggestions** list the steps before this one (nearest first), their fields (from the last run, or marked *expected* before any run), your variables and the functions, each with a short description.
- Under the field, a **preview** line shows the result at the current item ("→ Ada Lovelace · item 1 of 3"). It wraps to three lines with **Show all**.
- A problem is **underlined** where it is (amber for a warning, red for an error) and explained in the preview line, with a fix when there's an obvious one: *No step called "Get todo". Did you mean "Get todos"?* **Replace**.
- In a **Fixed** field, text that looks like a reference shows *This looks like a data reference* with **Show as expression** and **Use data…**.

### The full-screen editor

Press **Expand** next to an expression field, or <kbd>Ctrl</kbd>/<kbd>⌘</kbd>+<kbd>Shift</kbd>+<kbd>E</kbd>, to open the expression editor: the data, your expression and its result side by side (one tab each in the side panel). Step through the items to see the result for each; **Check all items** works the expression out for up to 500 items and lists the ones with problems.

## Text around values

Mix your own words with expressions in any text setting:

```txt title="Prompt"
Summarize the page at {{ $input.url }}.
Title: {{ $input.title }}
```

## Operators

**Fallbacks:** `||` returns the first value that isn't empty.

```txt title="Expression"
{{ $input.title || "Untitled page" }}
```

**Maths:** `+ - * / %`, with the usual precedence and parentheses.

```txt title="Expression"
{{ 5 + 3 * 2 }}        → 11
{{ (5 + 3) * 2 }}      → 16
{{ $input.price * 1.2 }}
```

**Joining text:** `+` joins text when either side is text.

```txt title="Expression"
{{ $input.first + " " + $input.last }}
```

**Comparisons and choices:** `== != < <= > >=`, logic with `&& || !`, and `condition ? ifYes : ifNo`.

```txt title="Expression"
{{ $input.total > 100 ? "big order" : "small order" }}
{{ $input.status == "open" && $input.priority == "high" }}
```

## Helper functions

Expressions are **sandboxed**: only the functions below exist. There are no variables of your own, no method calls like `.toUpperCase()`, and no access to anything outside the values you reference. Every function is safe: a wrong argument gives an explained problem, not a crash.

```txt title="Expression"
{{ upper(trim($input.name)) }}
{{ join($input.tags, ", ") }}
{{ formatDate($now, "EEEE d MMMM", "en", "Europe/Paris") }}
{{ addDays($today, 7) }}
{{ default($input.title, "Untitled") }}
```

Dates are ISO text (`2026-10-20T09:00:00Z`); a plain `YYYY-MM-DD` stays a calendar day. `$now` and `$today` are frozen when the step starts, so every item of one step sees the same time.

#### Text

| Function | What it does | Example | Result |
| --- | --- | --- | --- |
| `upper(text)` | The text in capital letters. | `upper("hello")` | `HELLO` |
| `lower(text)` | The text in small letters. | `lower("Hello")` | `hello` |
| `trim(text)` | The text without spaces or line breaks at either end. | `trim("  hi  ")` | `hi` |

| `replace(text, find, replaceWith)` | The text with every occurrence of find replaced. | `replace("a-b-c", "-", " ")` | `a b c` |
| `slice(textOrList, start, end?)` | The part from position start up to (not including) end. Counting starts at 0. | `slice("hello", 1, 3)` | `el` |
| `split(text, separator)` | The text cut into a list at each separator. | `split("a,b,c", ",")` | `a,b,c` |
| `join(list, separator)` | The items of a list as one text, with the separator between them. | `join(["a", "b"], " + ")` | `a + b` |
| `str(value)` | The value as text. | `str(42)` | `42` |
| `toTitleCase(text)` | Each word starting with a capital letter. | `toTitleCase("ada lovelace")` | `Ada Lovelace` |
| `toSnakeCase(text)` | The words in small letters joined with underscores. | `toSnakeCase("First Name")` | `first_name` |
| `slugify(text)` | A web-address-friendly version: small letters, no accents, words joined with dashes. | `slugify("Crème Brûlée Recipe!")` | `creme-brulee-recipe` |
| `stripTags(html)` | The text of an HTML snippet without its tags. | `stripTags("<p>Hello <b>you</b></p>")` | `Hello you` |
| `stripMarkdown(markdown)` | The text of a Markdown snippet without its formatting marks. | `stripMarkdown("**Bold** and [a link](https://example.com)")` | `Bold and a link` |
| `urlEncode(text)` | The text made safe to put inside a web address. | `urlEncode("a b&c")` | `a%20b%26c` |
| `urlDecode(text)` | The reverse of urlEncode. | `urlDecode("a%20b%26c")` | `a b&c` |
| `base64Encode(text)` | The text encoded as Base64 (UTF-8). | `base64Encode("hi")` | `aGk=` |
| `base64Decode(base64)` | The text a Base64 value holds (UTF-8). | `base64Decode("aGk=")` | `hi` |
| `padStart(text, length, fill?)` | The text made at least length characters long by adding fill (a space by default) in front. | `padStart(7, 3, "0")` | `007` |

| Function | What it does | Example | Result |
| --- | --- | --- | --- |

| `today()` | Today's date (YYYY-MM-DD), in the browser's time zone. | `today()` | `2026-10-19` |

## What an expression gives back

- In a field that holds **only** one `{{ … }}`, the value keeps its type in workflows with the [new behaviour](/app/workflows/behaviour-versions/): a number stays a number, a list a list, yes/no a boolean. In a text field, or with text around it, lists and objects become JSON text.
- Number and yes/no fields accept a mapped value: `"42"` becomes `42`, and `"yes"`, `"true"`, `"on"` or `"1"` become *true* (`"no"`, `"false"`, `"off"`, `"0"` or empty become *false*).
- A list of texts mapped into a text field keeps real line breaks inside its items.
- `"5" + 1` gives `"51"` (text joined), and `"5" * 2` gives `10`: the preview warns about the first and suggests `number(…)`.
- `{{ }}` text that isn't an expression (a Mustache or Handlebars template, an f-string) is kept exactly as written, braces included, with one warning in the run log. A `{{ }}` may span several lines.
- Code fields ([JavaScript Code](/nodes/builtin/core/javascript-code/), [Python Code](/nodes/builtin/core/code/)) never replace `{{ }}`: read data with `item` / `items` there.

### When an expression can't be worked out

In workflows with the **new behaviour**, an expression that can't be worked out (an unknown step, a typo in a function, a syntax error) **stops the step** with an error that names the field and the item, so **On error** and Try / Catch apply. In **Classic** workflows its text is kept and a warning is logged. A path that simply doesn't exist on the item stays empty in both.

### Coming from n8n?

AWFlow recognises n8n-style references and offers the AWFlow way, never changing your text by itself: `$json.x` → `$input.x`, `$('X').item.json.y` → `$('X').y`, `$node["X"].json.y` → `$('X').y`, and `$items()` / `$item`.

## You'll notice this when…

<details>
<summary>The field is underlined and the preview says "No step called …"</summary>

The `$('…')` name doesn't match any step before this one. Press **Replace** to use the suggested name, or tap the value in the **Input** pane instead of typing it.

</details>

<details>
<summary>The value is empty</summary>

The path doesn't exist on this item. Open the previous step's **Output** and compare: maybe the value is nested (`$input.data.title`), or a name has spaces and needs brackets (`$input["First name"]`).

</details>

<details>
<summary>The step fails with "… has not been set at this point in the run"</summary>

A `$run` value is read before the [Set Variable](/nodes/builtin/flow/setvariable/) step that writes it, or a `$vars` name isn't set on the [Variables](/app/variables/) page (the step then offers **Add NAME**).

</details>

<details>
<summary>An expression with .toUpperCase() doesn't work</summary>

Methods aren't available. Use the helper functions above, such as `upper(…)`, or move the logic to a [JavaScript Code](/nodes/builtin/core/javascript-code/) step.

</details>

<details>
<summary>A step shows an amber badge after a run</summary>

The run reported expression warnings for this step ("Ran with 2 warnings"). Hover the badge, or open the step: the fields concerned are underlined.

</details>
