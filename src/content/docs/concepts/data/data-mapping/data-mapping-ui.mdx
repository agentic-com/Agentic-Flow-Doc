:::note[In 20 seconds]
Mapping means "use a value from an earlier step here". Open a node's settings, find the value in the **Input** panel, and drag it into a field. AWFlow writes the expression for you, such as `{{ $input.title }}`. Mapping doesn't change any data: it only fills the setting, once for every item the node runs on.
:::

## See it happen

Get Page Metadata returns one item with the page's `url`, `title`, `canonicalUrl` and `description`. In Display Markdown, you drag **title** from the Input panel into the **Content** field. The field now holds `{{ $input.title }}`, and the run shows the real title.

## Tap a value into a field

Run the workflow (or the steps before this one) so they have data to show, then double-click the step to open its settings. On a wide screen, **Input** is the left column; in the side panel, pick **Input** in the **Input · Setup · Output** switch.

The first time you open a step with a mapped field, a short tip points at its pill and explains it.

**Use data** (the chip under a focused field in the side panel, or **Use data…** in the field's **⋯** menu) opens the same picker for that field: the previous step's fields with an item stepper, earlier steps, your variables, and the fields a step *promises* (marked **expected**) with a **Run** button when it hasn't run yet.

In [Edit Fields](/nodes/builtin/datatransformation/editfields/), **Add all fields from previous step** adds one row per field, and tapping a value adds a row for it.

## What gets written

| You pick… | The field gets… |
| --- | --- |
| A field of the step right before | `{{ $input.title }}` |
| A nested field | `{{ $input.metadata.description }}` (a dot path) |
| A field whose name has spaces or symbols | `{{ $input["First name"] }}` |
| A field of an earlier step | `{{ $('Get Page Metadata').title }}`, using the step's name. When that step has several items, the reference names the item (`$('X')[2].title`) and an amber **Uses item 3** note says so. |
| A variable | `{{ $vars.BASE_URL }}` |

Prefer the step right before when you can: a `$('…')` reference names a step, so check it after you rename one (the preview warns you if the name no longer matches). See [Item linking](/concepts/data/item-linking/).

You can mix mapped values with your own text in one field: `Summary of {{ $input.title }}`.

## You'll notice this when…

<details>
<summary>The Input pane shows no values, only a Run button</summary>

The steps before this one haven't run yet. Press **Run** there (or run the whole workflow once). Before any run, the fields a step promises are listed as **expected**, so you can already map them.

</details>

<details>
<summary>The preview says "No step called …"</summary>

The `$('…')` name doesn't match a step before this one, often after a rename. Press **Replace** to use the suggested name.

</details>

<details>
<summary>A Fixed field says "This looks like a data reference"</summary>

You typed `{{ … }}` in a field set to **Fixed**. It is filled in at run time either way; **Show as expression** shows it as a pill with a preview.

</details>

<details>
<summary>A mapped field is empty during the run</summary>

The field isn't on that item, or it's nested deeper than you mapped. Compare the path with the previous step's **Output**. Missing paths stay empty rather than failing the step.

</details>
