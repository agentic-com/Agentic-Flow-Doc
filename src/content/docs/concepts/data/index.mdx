Every step receives **items** and passes items on. An item is one record: a link, a product, an email. Most data problems come down to two questions: how many items reached this step, and where does the value you need sit inside them?

## Reading order

1. [Items](/concepts/data/data-structure/): what an item is, and why a step runs once per item.
2. [Mapping in the UI](/concepts/data/data-mapping/data-mapping-ui/): drag a field from an earlier step into a setting.
3. [Mapping with expressions](/concepts/data/data-mapping/data-mapping-expressions/): what `{{ $input.title }}` means, plus fallbacks, maths and helper functions.
4. [Item linking](/concepts/data/item-linking/): how values from earlier steps line up with the item being processed.
5. [Code](/concepts/data/code/): when a mapping isn't enough, reshape data with Python.

## Nodes that change the number of items

| Node | Items in → out |
| --- | --- |
| [Split Out](/nodes/builtin/datatransformation/splitout/) | One item holding a list → one item per list entry |
| [Aggregate](/nodes/builtin/datatransformation/aggregate/) | Many items → one item holding a list |
| [Filter](/nodes/builtin/flow/filter/) | Many → only the ones that match |
| [Limit](/nodes/builtin/datatransformation/limit/) | Many → the first or last few |
| [Remove Duplicates](/nodes/builtin/datatransformation/removeduplicates/) | Many → no repeats |
