Flow logic decides **what runs next**. Data mapping changes what an item looks like; flow logic changes the path the run takes through your workflow. Four questions cover almost everything: where does this item go, how do I repeat work, how do I pause, and what happens when a step fails?

## Reading order

1. [Workflow lifecycle](/concepts/flow/workflow-lifecycle/): what happens from the trigger to the last step.
2. [Execution order](/concepts/flow/execution-order/): which step runs when, and why branches wait for each other.
3. [Splitting and branching](/concepts/flow/splitting/): send items down different paths with IF, Switch or Filter.
4. [Merging](/concepts/flow/merging/): bring branches back together.
5. [Looping](/concepts/flow/looping/): repeat steps with Loop, Split in Batches or Poll Until.
6. [Waiting](/concepts/flow/waiting/): pause for a time or for a person.
7. [Error handling](/concepts/flow/error-handling/): retry, carry on, or catch a failure.

Then, when your workflows grow: [Lambda workflows](/concepts/flow/lambdaworkflows/) to reuse steps, and [Browser context](/concepts/flow/browser-context/) for steps that read or change a web page.
