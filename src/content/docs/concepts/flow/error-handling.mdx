:::note[In 20 seconds]
By default, a failing step ends the run. You can change that per step in its **Advanced** tab: **Try again automatically** retries, **On error** can **Continue with an empty result** or **Send to an error output** (failed items go down a red Error output while the others carry on). For a group of steps, **Try / Catch** sends a failure down a separate branch. An **Error Trigger** starts another workflow when a run fails.
:::

When a service answers 429 or 503 with a **Retry-After**, AWFlow waits at least that long (up to 5 minutes). The run log says each time: "Retry 1 of 2 (attempt 2 of 3)". Steps that call the network and were added by Aria or a template retry twice by default.

## Send failed items to an error output

With **On error** set to **Send to an error output**, the step gets a red **Error** output after its other outputs. When the step works on several items and some fail:

- each **failed item** goes down **Error**, as `{ error: { message, name }, input, itemIndex }`;
- the items that worked carry on through the normal output.

The normal output runs only if at least one item worked, and the Error output only if one failed; an unused side is skipped like an untaken If branch. The run is recorded as **Done with errors**, and the canvas shows an amber "2 failed → Error" badge on the step; its **Output** switches between **Success** and **Error**.

Some failures still stop the step: you pressed Stop, or you refused a permission. An Error output with nothing linked to it fails the step as before.

## Catch a failure with Try / Catch

Wire the steps you want to protect to the **Try** output of a [Try / Catch](/nodes/builtin/flow/try/) node, and the plan B to **Catch**. Bring both branches back into the same step to mark where the guarded part ends.

```mermaid
flowchart LR
  S[Start] --> T{Try / Catch}
  T -->|Try| F[Get Element Data] --> P[Edit Fields]
  T -->|Catch| A[Send an alert]
  P --> J[Save]
  A --> J
  class T awf-flow
  class F,P awf-data
  class A awf-err
  class J awf-ok
```

If a guarded step fails, the rest of the Try branch is skipped and Catch runs with `nodeLabel`, `message` and `input`. A failure inside the Catch branch isn't caught by the same Try: it goes to an outer Try / Catch, or ends the run.

To stop a run on purpose with a clear message, use [Stop and Error](/nodes/builtin/flow/stopanderror/).

## Hear about failed runs

An [Error Trigger](/nodes/builtin/trigger/errortrigger/) starts a workflow when a watched workflow fails. It receives the failed workflow, the step that failed, the error and its input. It fires for runs that start on their own (a schedule, a page load, a hotkey and so on), not for runs you start yourself from the editor, and not for failures a Try / Catch already handled. A failed run is always recorded as **Failed** (never **Canceled**), so the Error Trigger sees it.

[Workflow settings](/app/workflows/settings/#when-this-fails) › **When this fails** lists the workflows that watch this one and can **Create an error workflow** for you.

## You'll notice this when…

<details>
<summary>One failing step ended the whole run</summary>

That's the default. Turn on **Try again automatically** or change **On error** in the step's **Advanced** tab, or guard it with [Try / Catch](/nodes/builtin/flow/try/).

</details>

<details>
<summary>A step kept retrying a "401 Unauthorized" error</summary>

**Which errors** is set to *Any error*. Set it to *Temporary only* so the step fails fast when the problem won't go away, then fix the connection.

</details>

<details>
<summary>The steps after a failed step get an empty item</summary>

That's how **Continue with an empty result** works: the failed step outputs one empty item. Add a fallback in later expressions, such as `{{ $input.title || "Untitled" }}`, or check for it with an [If](/nodes/builtin/flow/if/), or use **Send to an error output** instead.

</details>

<details>
<summary>The Error Trigger didn't fire</summary>

You started the run yourself, a Try / Catch handled the failure, or the alert workflow isn't **On**. See the [Error Trigger rules](/nodes/builtin/trigger/errortrigger/).

</details>

<details>
<summary>A page step fails with an element not found</summary>

The page changed, or it wasn't ready yet. Add [Wait For Element](/nodes/extension/ui/wait-for-element/) before the step, and check the selector still matches. See [Browser context](/concepts/flow/browser-context/).

</details>
