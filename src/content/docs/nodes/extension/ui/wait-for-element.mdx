Wait for an element condition in the opened page

## What it does

Pauses workflow execution until a specified element appears, disappears, or meets a condition.

## When to use it

Use this node to handle dynamic content, wait for page loads, or ensure elements are ready before interaction.

## Inputs and settings

{/* AUTO:settings:start */}
| Setting | Type | Default | Required | Description |
| --- | --- | --- | --- | --- |
| **DOM Selector** | Page element |  | Yes | The selector of the DOM element to interact with. |
| **Condition** | Choice | exists | Yes | Choose what condition to wait for. Options: exists, visible, hidden, containsText. |
| **Text** | Text |  | No | Text required for the Contains Text condition. |
| **Timeout** | Number | 5000 | No | Maximum time to wait in milliseconds. |
| **Polling interval** | Number | 100 | No | How often to check in milliseconds. |
{/* AUTO:settings:end */}

## Outputs

{/* AUTO:outputs:start */}
One output port.

Each output item has the fields `waitResult` (object).
{/* AUTO:outputs:end */}

## Dependencies and credentials

{/* AUTO:deps:start */}
None. This node needs no credential and has no slots for other nodes.
{/* AUTO:deps:end */}

## Example workflow

Run Wait For Element after opening the target page, then pass its output to Edit Fields, an AI node, or an integration node.

## Troubleshooting

- Check that required settings are present before running the node.
- If the node uses browser page data, run it on the target tab after the page has loaded.
- If it calls an external service, verify credentials, permissions, and rate limits.
