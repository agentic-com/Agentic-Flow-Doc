# Lambda Workflow

Runs a reusable workflow as a node. Its input schema is derived from the selected lambda workflow input node.

## What it does

Executes a reusable lambda workflow as a node within a larger workflow.

## When to use it

Use this node to call modular sub-workflows, enabling workflow composition and reusability.

## Inputs and settings

| Setting | Notes |
| --- | --- |
| Node form | This node uses the default workflow node configuration. |

## Outputs

Passes data into or out of a lambda workflow, or exposes a lambda workflow as a reusable node.

## Pausing inside a sub-workflow

A lambda workflow can contain a step that pauses — a [Wait For Approval](/nodes/builtin/flow/wait-for-approval/), an [In-Page Form](/nodes/builtin/flow/), a durable [Wait](/nodes/builtin/flow/wait/), or a [Poll Until](/nodes/builtin/flow/polluntil/). When it does, the whole run pauses: the sub-workflow waits (you'll see it in the Executions pane), and the outer workflow waits at this node. When the sub-workflow finishes, its output flows into this node and the outer workflow continues — so a reusable "get an approval" or "wait for the job" sub-workflow works exactly like a single pausing step, at any nesting depth.

## Dependencies and credentials

- No explicit credential or node dependency is declared in the node description.

## Example workflow

Connect data into Lambda Workflow, configure the settings above, and use the output in the next workflow step.

## Troubleshooting

- Check that required settings are present before running the node.
- If the node uses browser page data, run it on the target tab after the page has loaded.
- If it calls an external service, verify credentials, permissions, and rate limits.
- This node has source tests; use them as the reference for edge-case behavior during maintenance.
