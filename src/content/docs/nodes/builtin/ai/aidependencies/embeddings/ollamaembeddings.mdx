Turn text into vectors with an embedding model running in Ollama on your computer: free, private, no API key.

## What it does

Ollama Embeddings plugs into the **Embeddings** slot of a [Local Knowledge](/nodes/builtin/ai/aidependencies/vectorstore/localknowledge/) node. It does not run on its own and has no output. When the knowledge base is filled or searched, the text goes to the Ollama app on your computer, at `http://localhost:11434`, and comes back as vectors (lists of numbers that capture meaning). Nothing leaves your machine.

A knowledge base remembers the embedding model it was built with and always uses it. So this node decides the model when a **new, empty** knowledge base is first filled. After that, connect the same node to search it.

## When to use it

- You already run Ollama and want a specific open embedding model, such as `nomic-embed-text`.
- Private documents that must not go to a cloud service, with a model you choose in Ollama.

With nothing to install, [Local Embeddings](/nodes/builtin/ai/aidependencies/embeddings/localembeddings/) also runs on your device.

## Inputs and settings

{/* AUTO:settings:start */}
| Setting | Type | Default | Required | Description |
| --- | --- | --- | --- | --- |
| **Model** | Model picker |  | Yes | The model to use. |
{/* AUTO:settings:end */}

The **Model** list shows the models installed in your Ollama; use the refresh button after you pull a new one. Pick an embedding model (for example after `ollama pull nomic-embed-text`), not a chat model.

Ollama must allow AWFlow to call it. Start it with:

- Chrome: `OLLAMA_ORIGINS=chrome-extension://linlkeaipfpnhddjkpcbmldionajfifa ollama serve`
- Firefox: `OLLAMA_ORIGINS=moz-extension://* ollama serve`

When you publish or share the workflow, **Model** is cleared, so whoever installs it picks a model from their own Ollama.

## Outputs

{/* AUTO:outputs:start */}
This node has no output port. It plugs into a slot on another node instead of passing items along.

| Slot | Accepted by |
| --- | --- |
| Embeddings | [Local Knowledge](/nodes/builtin/ai/aidependencies/vectorstore/localknowledge/) |
{/* AUTO:outputs:end */}

The vectors go to the knowledge base, not to the next node.

## Example workflow

1. A [Context Menu](/nodes/builtin/trigger/contextmenu/) trigger on the page.
2. [Get All Text](/nodes/extension/getalltext/) with **Output field name** `pageText`.
3. [Indexer](/nodes/builtin/ai/aiagents/indexernode/) with **Input** `{{ $input.pageText }}`, a [Recursive Character Text Splitter](/nodes/builtin/ai/aidependencies/textsplitter/recursivecharactertextsplitter/) in its **Text Splitter** slot, and a [Local Knowledge](/nodes/builtin/ai/aidependencies/vectorstore/localknowledge/) pointing to a new knowledge base in its **Knowledge** slot.
4. Ollama Embeddings in the Local Knowledge's **Embeddings** slot, **Model** `nomic-embed-text:latest`.

## Troubleshooting

- **"Could not reach Ollama at localhost:11434. Make sure it is running and allows this extension (OLLAMA_ORIGINS)."** Start Ollama, and restart it with `OLLAMA_ORIGINS` set as shown above.
- **The list says "No models available".** Pull an embedding model, then press the refresh button.
- **"… was built with … embeddings. Connect that embeddings node to use it."** The knowledge base was built with this Ollama model. Connect Ollama Embeddings with the same **Model**, and make sure Ollama is running.
- **A "Model mismatch" warning in the run log.** The knowledge base was built with another model, so this node was ignored. Disconnect it, or re-embed the knowledge base from its settings.
