# Sentiment Analysis

Analyze the sentiment of a text using a LLM

## What it does

Sends the input text to a language model and asks it to classify the sentiment as one of `positive`, `negative`, or `neutral` by default, or into a custom set of categories you define. The model is instructed to respond with only the category name, with no explanation.

It can also run **on-device**: switch **Engine** to *On-device* to classify with a local moderation model that runs entirely in your browser — free, private, and offline, with no LLM connection required. See [Local AI](/usage/using-the-app/local-models/).

## When to use it

Use this node to classify the tone of customer feedback, reviews, support tickets, or social media text — for example, routing negative feedback to a different workflow branch than positive feedback.

## Inputs and settings

| Setting | Notes |
| --- | --- |
| Text | The text to analyze the sentiment of. Rendered as a text area. |
| Engine | **LLM** (a connected chat model) or **On-device** (a local classifier — free, offline). |
| On-device model | *(Engine = On-device)* Any installed text-moderation model, across engines. |
| Options → Custom categories | Comma-separated list of custom sentiment categories to use instead of the default positive/negative/neutral. Rendered as a text area. |
| Options → System message | Optional additional system message appended to the analysis instructions. Rendered as a text area. |

## Outputs

- **LLM engine** — returns `{ sentiment }`, the trimmed category name returned by the model (one of the default three categories, or one of your custom categories).
- **On-device engine** — returns `{ sentiment, score, predictions }`: the top label, its confidence, and the full list of `{ label, score }` predictions. (Custom categories and System message don't apply here — the local model's own labels are used.)

## Dependencies and credentials

- **Model** (required for the LLM engine) — connect a language model dependency (e.g. Chat OpenAI). Not needed for the on-device engine.

## Example workflow

Connect a Chat OpenAI node to the Model dependency, feed text from an upstream node into Text, optionally set Custom categories (e.g. "angry, satisfied, confused"), then branch downstream logic on the `sentiment` output using a router or condition node.

## Troubleshooting

- If the output includes extra words instead of just the category, add a stronger instruction via the System message option, or verify the connected model follows instructions well.
- **LLM engine** — verify the Model dependency is connected; the node throws if no model is found (or switch Engine to On-device).
- **On-device engine** — choose an on-device model; the node throws if the field is empty or the model isn't installed. Install one from the picker or the [Local AI](/usage/using-the-app/local-models/) page.
- Keep Custom categories short and mutually exclusive so the model can reliably pick one.
