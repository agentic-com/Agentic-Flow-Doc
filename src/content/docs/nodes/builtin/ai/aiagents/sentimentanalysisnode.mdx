# Sentiment Analysis

Analyze the sentiment of a text using a LLM, or on-device with a Local Classifier

## What it does

Sends the input text to a language model and asks it to classify the sentiment as one of `positive`, `negative`, or `neutral` by default, or into a custom set of categories you define. The model is instructed to respond with only the category name, with no explanation.

It can also run **on-device** — see [Run on-device](#run-on-device).

## Run on-device

What you connect to the **Model** port decides the engine:

- **A chat model** (e.g. Chat OpenAI, Web LLM) — the LLM path described above.
- **A [Local Classifier](/nodes/builtin/ai/aidependencies/llm/localclassifier/)** — classifies in your browser: free, private, offline. A fixed-label sentiment model uses its own labels, mapped onto `positive` / `negative` / `neutral` (e.g. `POSITIVE`/`NEGATIVE`, `1 star`–`5 stars`). A **zero-shot** model scores your **Custom categories** (kept verbatim), or `positive, negative, neutral` when none are set. System message doesn't apply.

**Older workflows:** the node used to have an **Engine** setting (*LLM* / *On-device*) with an **On-device model** field. That setting is now hidden but still honoured: a workflow saved with Engine = *On-device* and nothing connected to the Model port keeps running its chosen on-device model, with the same output as before. To change it, connect a Local Classifier instead.

## When to use it

Use this node to classify the tone of customer feedback, reviews, support tickets, or social media text — for example, routing negative feedback to a different workflow branch than positive feedback.

## Inputs and settings

| Setting | Notes |
| --- | --- |
| Text | The text to analyze the sentiment of. Rendered as a text area. |
| Options → Custom categories | Comma-separated list of custom sentiment categories to use instead of the default positive/negative/neutral. Rendered as a text area. |
| Options → System message | Optional additional system message appended to the analysis instructions. Rendered as a text area. |

## Outputs

- **Chat model** — returns `{ sentiment }`, the trimmed category name returned by the model (one of the default three categories, or one of your custom categories).
- **Local Classifier** — returns `{ sentiment, score, scores }`: the top label, its confidence, and a `{ label: score }` map of every label.
- **Legacy Engine = On-device** (older workflows) — returns `{ sentiment, score, predictions }`: the model's raw top label, its confidence, and the list of `{ label, score }` predictions.

## Dependencies and credentials

- **Model** (required) — connect a language model dependency (e.g. Chat OpenAI), or a [Local Classifier](/nodes/builtin/ai/aidependencies/llm/localclassifier/) to run on-device.

## Example workflow

Connect a Chat OpenAI node to the Model dependency, feed text from an upstream node into Text, optionally set Custom categories (e.g. "angry, satisfied, confused"), then branch downstream logic on the `sentiment` output using a router or condition node.

## Troubleshooting

- If the output includes extra words instead of just the category, add a stronger instruction via the System message option, or verify the connected model follows instructions well.
- **"Connect a chat model or a Local Classifier to the Model port."** — nothing is connected to the Model port.
- **On-device** — the Local Classifier needs an installed model; install one from the picker or the [Local AI](/usage/using-the-app/local-models/) page.
- Keep Custom categories short and mutually exclusive so the model can reliably pick one.
