Retrieve and generate an action plan and execute it. Can use external tools.

## What it does

Retrieves relevant information from a knowledge base and generates answers using an LLM with optional tool usage.

## When to use it

Use this agent when you need to answer questions using information from indexed documents or knowledge bases.

## Inputs and settings

| Setting | Notes |
| --- | --- |
| System message | Extra instructions for the model. |
| Options → Knowledge documents (k) | How many passages to retrieve from the connected knowledge base (default `4`). |
| Options → Max knowledge context length | Maximum characters of retrieved passages added to the prompt (default `4000`). |
| Options → Fail on knowledge error | Fail when the knowledge base can't be searched, instead of answering without it (default off). |
| Options → Search type, Match by, Minimum relevance, Metadata filter, Device-only knowledge with a cloud model | See [Knowledge base options](#knowledge-base-options). |

## Knowledge base options

These options are the same on the RAG Agent, the [Q&A Agent](/nodes/builtin/ai/aiagents/qanode/) and the [Tools Agent](/nodes/builtin/ai/aiagents/toolsagentnode/). They apply to the [Local Knowledge](/nodes/builtin/ai/aidependencies/vectorstore/localknowledge/) connected to the Knowledge port.

| Option | Notes |
| --- | --- |
| **Search type** | **Most similar** (default) — the passages closest to the question. **Diverse (MMR)** — close to the question but different from each other, so fewer repeats. |
| **Match by** | Used with *Most similar*. **Keywords and meaning** (default) also finds exact words, names and codes. **Meaning only** uses vector similarity alone. *Diverse (MMR)* and other vector stores always match by meaning. |
| **Minimum relevance** | From `0` to `1`. Passages less similar to the question than this are dropped. `0` (default) keeps every passage. |
| **Metadata filter** | Only search passages whose metadata matches every `key = value`, for example `sourceType: web`. Keys use letters, numbers and `_`; numbers and `true`/`false` are matched as such. |
| **Device-only knowledge with a cloud model** | What to do when the knowledge base is *Device only* and the connected model is a cloud model. **Stop with an error** (default) — the node fails and says why. **Answer without it** — the node runs without the knowledge base and logs a warning. |

Useful metadata keys for the filter: `sourceType` (`file`, `web`, `tab`, `text`, `workflow`, `chat`), `sourceId`, `title`, `url`, `fileName`, `page`.

### Device-only knowledge bases

A knowledge base marked **Device only** (see [Privacy](/usage/using-the-app/knowledge-bases/overview/#privacy-cloud-ok-or-device-only)) is never sent to a cloud model. Models that count as on-device: Web LLM, Transformers Chat, Ollama, Chrome AI, Local Q&A Model and Local Classifier. With any other model, the node either stops with "*"Legal templates" is on this device only, but … is a cloud model. Use an on-device model or change the knowledge base's privacy.*" or answers without it, depending on the option above.

### Passages are reference data

Retrieved passages are added to the prompt inside a fenced block marked as reference data, not instructions. A document that contains text like "ignore your instructions" is treated as content to quote, not as a command.

## Outputs

| Field | Description |
| --- | --- |
| `response` | The answer. |
| `sources` | Present when a knowledge base is connected (may be empty): the sources of the passages used, each with `title`, `url` (when there is one), `knowledgeId`, `sourceId` and `score`. |

After a run, the node shows a badge such as **3 sources cited**.

## Dependencies and credentials

- **Model** (required) — a chat model.
- **Knowledge** (optional) — a [Local Knowledge](/nodes/builtin/ai/aidependencies/vectorstore/localknowledge/) node.
- **Memory** and **Output Parser** (optional).

## Memory

Connect a chat memory to the agent's memory input to give it a conversation:

1. Before calling the model, the agent loads the conversation's earlier messages and adds them to the prompt as chat history.
2. It saves the incoming prompt as a `user` message.
3. After the model answers, it saves the reply as an `assistant` message (structured replies from an output parser are saved as JSON text).

Use a [Chat Memory](/nodes/builtin/ai/aidependencies/chatmemories/chatmemory/): with **Conversation** or **Key** storage the conversation is kept across runs; with **This run only** it lasts for one run. It sends as much history as fits the connected model (or the last N messages), and summarises what no longer fits.

This is also how a [Chat Trigger](/nodes/builtin/trigger/chat/) gets its replies: connect the **same** memory to the trigger and to this agent, and set the prompt to `{{ $json.chatInput }}`. The chat window shows the messages this agent saves.

## Example workflow

Connect a chat model to the Model port and a [Local Knowledge](/nodes/builtin/ai/aidependencies/vectorstore/localknowledge/) to the Knowledge port, then send questions to the agent. The answer comes back in `response` and the documents it used in `sources`.

## Troubleshooting

- **"… is on this device only, but … is a cloud model."** — see [Device-only knowledge bases](#device-only-knowledge-bases).
- **"Knowledge base "…" doesn't exist on this device…"** — pick a knowledge base in the Local Knowledge node, or import its `.awkb` file.
- **No or few passages** — lower **Minimum relevance**, check the **Metadata filter**, or try the question in the knowledge base's **Test search** tab.
- If it calls an external service, verify credentials, permissions, and rate limits.
