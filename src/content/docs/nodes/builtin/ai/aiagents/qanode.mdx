Generate an action plan and execute it. Can use external tools.

## What it does

Answers questions using a knowledge base by retrieving relevant context and generating responses.

## When to use it

Use this agent to build question-answering systems that reference specific documents or knowledge bases.

## Run on-device

What you connect to the **Model** port decides the engine — there is no setting to switch:

- **A chat model** (e.g. Chat OpenAI, Web LLM) — retrieves passages from the connected Knowledge and writes an answer from them.
- **A [Local Q&A Model](/nodes/builtin/ai/aidependencies/llm/localqamodel/)** — answers in your browser: free, private, offline. It retrieves the top passages from the connected Knowledge and **quotes** the best-scoring answer span, so the answer always comes verbatim from your documents. System message and Output Parser don't apply.

The on-device path **needs a Knowledge**: an extractive model can only quote from a passage, so connect a [Local Knowledge](/nodes/builtin/ai/aidependencies/vectorstore/localknowledge/) (pair it with [Local Embeddings](/nodes/builtin/ai/aidependencies/embeddings/localembeddings/) to keep everything on-device).

| Options › **Metadata filter** | Key-value pairs |  | No | Only search passages whose metadata matches every key = value (e.g. sourceType = web). Keys use letters, numbers and \_; numbers and true/false are matched as such. |
| Options › **Device-only knowledge with a cloud model** | Choice | Stop with an error | No | A knowledge base marked "Device only" is never sent to a cloud model. Choose what the node does when its model is a cloud model. Options: Stop with an error, Answer without it. |

Retrieved passages are added to the prompt as fenced reference data, not instructions. A knowledge base marked **Device only** is never sent to a cloud model: by default the node stops with an error; set **Device-only knowledge with a cloud model** to *Answer without it* to run without it and log a warning. The Local Q&A Model runs on-device, so it can always use it.

## Outputs

{/* AUTO:outputs:start */}
One output port.

Each output item has these fields:

| Field | Type | Description |
| --- | --- | --- |
| `response` | Any | The model reply; the parsed result when an output parser is connected |
| `answer` | Text |  |
| `score` | Number |  |
| `source` | Text |  |
| `sources` | List of entries | The knowledge base sources used for the answer |
{/* AUTO:outputs:end */}

- **Chat model** — returns `{ response, sources }`: the generated answer and the sources of the passages used.
- **Local Q&A Model** — returns `{ response, answer, score, source, sources }`: `response` and `answer` are the quoted answer (empty if none was found), `score` is the model's confidence, and `source` names the document it came from (when its metadata has a source, file name, title, or URL).

`sources` is present when a knowledge base is connected (it may be empty). Each entry has `title`, `url` (when there is one), `knowledgeId`, `sourceId` and `score`. After a run, the node shows a badge such as **3 sources cited**.

- **Output Parser** (optional) — chat model only.

## Example workflow

Connect Local Embeddings → Local Knowledge → the Q&A Agent's Knowledge port, and a Local Q&A Model to its Model port. Add your documents to the knowledge base (on the [knowledge bases page](/usage/using-the-app/knowledge-bases/overview/) or with the [Indexer](/nodes/builtin/ai/aiagents/indexernode/)), then send questions to the agent — the answer and its source document come back without anything leaving the browser.

## Troubleshooting

- **"… it needs a context: connect a Knowledge to the Q&A Agent."** — the Local Q&A Model is connected but no Knowledge is.
- **Empty `answer` on-device** — no retrieved passage contained an answer (a warning is logged). Raise Knowledge documents (k) or rephrase the question.
- **"Knowledge retrieval failed: …"** — the knowledge store couldn't be searched; check the Local Knowledge node and its embeddings.
- **"… is on this device only, but … is a cloud model."** — the knowledge base is *Device only*. Use an on-device model (such as the Local Q&A Model), change the knowledge base's privacy, or set **Device-only knowledge with a cloud model** to *Answer without it*.
- If it calls an external service, verify credentials, permissions, and rate limits.
