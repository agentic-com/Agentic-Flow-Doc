Splitting text into chunks and embedding them into a vector store

## What it does

Splits text into chunks and saves them, with their embeddings, into the connected knowledge base so agents can search them later.

## When to use it

Use it to fill a [knowledge base](/usage/using-the-app/knowledge-bases/overview/) from a workflow: pages you scrape, files you load, results of an API call. To add files, pages or text by hand, use **Add sources** on the knowledge bases page instead.

## Inputs and settings

{/* AUTO:settings:start */}
| Setting | Type | Default | Required | Description |
| --- | --- | --- | --- | --- |
| **Input** | Text |  | Yes | The input to index. |
| **Source ID** | Text |  | No | A stable id for this document. Indexing again with the same id updates it instead of adding a copy. Defaults to the source link or name, else to the text itself. |
| **Source name** | Text |  | No | Shown in citations and in the knowledge base source list. Indexing again with the same source name (or link) updates that source in place instead of adding a copy. |
| **Source link** | Text |  | No | Where the text comes from, linked from citations. |
{/* AUTO:settings:end */}

### Update in place

Indexing again with the **same source** updates it instead of adding a copy. The source is identified by its Source ID, or else its Source link, or else its Source name. Its passages are overwritten in place, and if the new text is shorter, the old passages beyond it are removed.

Give each document a Source name or Source link (or an ID) when a workflow re-indexes the same pages on a schedule; without one, a changed text counts as a new source.

## Outputs

Each output item has these fields:

| Field | Type | Description |
| --- | --- | --- |
| `success` | True/false |  |
| `chunks` | Number |  |
| `added` | Number |  |
| `updated` | Number |  |
| `failed` | Number |  |
| `removed` | Number |  |
| `sourceId` | Text |  |
{/* AUTO:outputs:end */}

| Field | Description |
| --- | --- |
| `success` | `false` when some chunks could not be saved (see `failed`). |
| `chunks` | How many chunks the input was split into. |
| `added` | New chunks written. |
| `updated` | Chunks that replaced the same source's previous version. |
| `failed` | Chunks that could not be saved. |
| `removed` | Old chunks removed because the source got shorter. |
| `sourceId` | The source the chunks are stored under. Index again with the same id to update it. |

After a run, the node on the canvas shows a badge such as **24 added · 3 updated**, and the node settings show the last run's **Added / Updated / Failed** counts. When some chunks fail, the run log has a warning; when none can be saved, the node fails.

With a vector store other than Local Knowledge, the chunks are simply added (`updated` is always 0).

## Dependencies and credentials

{/* AUTO:deps:start */}
| Slot | Accepts | Required | Connections |
| --- | --- | --- | --- |
| **Model** | chat model | No | One |
| **Knowledge** | vector store | Yes | One |
| **Text Splitter** | text splitter | Yes | One |
{/* AUTO:deps:end */}

- **Knowledge** (required) — a [Local Knowledge](/nodes/builtin/ai/aidependencies/vectorstore/localknowledge/) node. The chunks are embedded with that knowledge base's own model.
- **Text Splitter** (required) — how the text is split, for example [Recursive Character Text Splitter](/nodes/builtin/ai/aidependencies/textsplitter/recursivecharactertextsplitter/).
- **Model** (optional) — not used for indexing. Existing workflows that have one connected keep working.

## Example workflow

A Schedule Trigger → HTTP Request (or a page extraction node) → Indexer, with Local Knowledge and a text splitter connected to the Indexer. Set **Source link** to the page URL so each run updates the same source, and citations in chats link back to it.

## Troubleshooting

- **"None of the N chunks could be saved to the knowledge base."** — nothing was written; check the knowledge base and its embedding model in [Local AI](/usage/using-the-app/local-models/).
- **"N of M chunks could not be saved…"** (warning) — part of the text was saved; `success` is `false` and `failed` counts the rest.
- **Duplicates after each run** — set a Source name, Source link or Source ID so the same document is updated in place.
- **Citations read "Workflow input"** — set a Source name.
