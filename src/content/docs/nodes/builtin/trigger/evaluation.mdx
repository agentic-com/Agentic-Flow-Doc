## What it does

The Evaluation Trigger never starts a normal run: pressing **Run** ignores it, and it doesn't run on a schedule or any other trigger. Only **Run evaluation** in the canvas **⋯** menu › **Test runs** uses it. Each row becomes one run, and the row's columns are this trigger's output.

Rows come from:

- **Data Store**: a **Dataset** key that holds a list of rows, or a key prefix ending in `*` (one row per key, in key order). **Whose keys** picks this workflow's keys or all workflows'.
- **CSV**: rows pasted in the step, with a header line.

**Up to** caps the rows per evaluation run (50 by default, at most 500).

- **Google Sheets**: a sheet read with the step's Google connection (the spreadsheet's link or ID, and the worksheet's gid). The first row names the columns; each non-empty row below is a case.

To add a real run as a case, open it in [Runs](/app/workflows/run-history/#add-a-run-to-a-test-dataset) and use **Add this run's input to the test dataset** (Data Store lists only, not a key prefix).

## When to use it

- Before changing the model or the prompt of an AI workflow: run the same cases before and after, and compare.
- To keep a set of tricky inputs that once went wrong, and check they stay fixed.

See [Test runs](/app/workflows/test-runs/) for the whole method.

```csv title="Pasted CSV"

```

## Common issues

- **"The dataset has no rows."**: the key is empty, or no key starts with the prefix.
- **"Paste the CSV rows, with a header line."**: the CSV box is empty.
- **"Save first: test runs use the saved workflow."**: Test runs always run the saved version. Save, then run the evaluation.
