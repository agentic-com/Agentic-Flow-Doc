Start the workflow when an issue or a pull request is opened, or updated, in a GitHub repository.

:::note[A polling trigger]
It checks for new items on a timer while the workflow is **On**, in the browser extension. Read [Polling triggers](/concepts/flow/polling-triggers/) for the first check, test events and what happens when a check fails.
:::

## What it does

Every **Check every** minutes, the trigger reads the repository's latest issues or pull requests (**Watch**) and starts one run with the new ones. With **Start a run when one is** set to **Updated**, every new change to an issue counts again. The issue trigger never starts a run for a pull request.

A check that finds nothing new starts no run. Press **Run** to fetch a test event: the latest items, without moving the trigger's position.

## When to use it

- Post new issues to a team channel.
- Label or triage new pull requests with AI.
- Copy new issues to Linear or Todoist.

## Example workflow

1. New issue or pull request, **Watch** Issues, **Opened**.
2. [Text Classifier](/nodes/builtin/ai/aiagents/textclassifiernode/) sorts it into bug / question / idea.
3. [Slack](/nodes/builtin/integration/slack/) posts it to the matching channel.

## Common issues

- **"Repository: use owner/repo."**: type it as `owner/repo`, or paste the full link.
- **GitHub answered 404**: the connection's token can't see that repository.
