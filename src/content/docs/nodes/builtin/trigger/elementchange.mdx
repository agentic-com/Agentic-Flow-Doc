Run the flow when any of one or more CSS selectors on a matching page changes.

## What it does

Watches one or more elements on any open tab whose URL matches the configured patterns. The extension injects a `MutationObserver` for each selector while the page is open, and fires the workflow when any watched element meets the chosen condition. The trigger only runs inside the awflow browser extension — never in the web app.

## When to use it

Use this trigger to react to live changes on a page without polling: a price updating, a "Back in stock" badge appearing, a status line changing, or a headline matching a keyword. Add several selectors to one node when the same reaction should fire for any of a set of elements.

## Inputs and settings

{/* AUTO:settings:start */}
| Setting | Type | Default | Required | Description |
| --- | --- | --- | --- | --- |
| **CSS Selectors** | List |  | Yes | One or more elements to watch. The flow fires when any of them meets the condition. Use the crosshair to pick an element on the page. |
| **Fire when** | Choice | Content changes | No | Options: Content changes, Element appears, Element disappears, Text matches. |
| **Match text** | Text |  | No | Text to match when condition is "Text matches". |
| **Debounce (ms)** | Number | 500 | No | SPAs mutate constantly; debounce coalesces bursts into one fire. |
| **URL Patterns** | Tags | `["<all_urls>"]` | No |  |
{/* AUTO:settings:end */}

The condition, match text, debounce, and URL patterns are shared by every selector in the list.

## Outputs

{/* AUTO:outputs:start */}
One output port.

Each output item has the fields `triggerType` (choice), `triggeredAt` (text), `selector` (text), `condition` (text), `url` (text), `tabId` (number), `matchedText` (text).
{/* AUTO:outputs:end */}

When a watched selector fires, the workflow starts with this trigger context:

| Field | Notes |
| --- | --- |
| `triggerType` | Always `elementChange`. |
| `selector` | The single selector that fired (not the whole list). |
| `condition` | The condition that was met. |
| `url` | The page URL where the change happened. |
| `matchedText` | The element's text at the moment it fired. |
| `tabId` | The tab the change happened in. |

## Dependencies and credentials

{/* AUTO:deps:start */}
None. This node needs no credential and has no slots for other nodes.
{/* AUTO:deps:end */}

- Runs inside the awflow browser extension only.

## Example workflow

Add an Element Change trigger, add a row for each element you want to watch (for example `.price` and `.availability`), set *Fire when* to **Content changes**, and restrict *URL Patterns* to the product page. Connect it to a notification node so you are alerted whenever either element changes.

## Troubleshooting

- If nothing fires, confirm the tab's URL matches one of the *URL Patterns* and that each selector actually matches an element on the page — use the crosshair to pick it, or the ping button to highlight the current selector.
- On single-page apps, raise the debounce if the flow fires more often than expected.
- **Text matches** fires on the transition into a match, not on every mutation while the text keeps matching.
- Blank selector rows are ignored; at least one non-empty selector must remain.
- Workflows saved before the selector list existed keep working: their single selector is honoured as a one-item list.
