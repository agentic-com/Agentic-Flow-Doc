Stop the run on purpose, with an error message you write.

## What it does

When data reaches Stop and Error, the node fails right away with your message. The run stops and shows as failed, as if any other step had failed. Nothing can be connected after it.

The message comes from a field named `message` in **Fields**. Without one, the error reads `Error throwed by : <Stop and Error node>`.

A failure from this node behaves like any other failure: a [Try / Catch](/nodes/builtin/flow/try/) around it sends it to the **Catch** branch, and an [Error Trigger](/nodes/builtin/trigger/errortrigger/) workflow can react to it.

## When to use it

- Stop when the data is wrong: after an [IF](/nodes/builtin/flow/if/), end the run if a required field is empty.
- Stop when a page didn't load what you expected, instead of saving empty results.
- Make a run show as failed, with a clear reason, so an error workflow can alert you.

To simply drop items without failing, use [Filter](/nodes/builtin/flow/filter/), or leave an IF branch unconnected.

## Example workflow

Stop when a page has no price:

1. [Get Element Data](/nodes/extension/getelementdata/) with **Output field name** `price` reads the price on the open page.
2. [IF](/nodes/builtin/flow/if/) with the condition `{{ $input.price }}` (**String**) **Is Empty**.
3. From **True**: Stop and Error with a field `message` set to `No price found on this page`.
4. From **False**: [Google Sheets](/nodes/builtin/integration/google-sheets/) appends the price.

## Troubleshooting

- **The error says `Error throwed by : <Stop and Error node>`.** No field is named exactly `message`. Rename the key (it is case-sensitive).
- **The run fails even though the data looks fine.** Data reached Stop and Error, so check the IF or Switch in front of it: open the run and see which branch the item took.
