Send a message back to the chat that started the run. Use it to control exactly what the chat shows, or to ask a follow-up question and wait for the answer.

## What it does

In a workflow started by a [Chat Trigger](/nodes/builtin/trigger/chat/), the reply in the chat comes from a **reply step**: a Respond to Chat step, or else the last AI step on the trigger's path. The reply streams into the chat as it is written.

Respond to Chat sends its **Message**. Then, depending on **After sending**:

- **Carry on**: the run continues straight away.
- **Wait for the reply**: the run pauses until the person writes the next chat message. That message becomes this step's output, and the run continues from here.

With **Add to chat memory** on (the default), the message is also stored in the Chat Memory connected to the Chat Trigger, so an agent later in the chat remembers it.

When no chat is open for the run (it was started another way), the message is only stored in the chat memory and the run log says so.

## When to use it

- A fixed reply: "Got it, your ticket is #1234."
- Combining several results into one message, after steps that are not AI steps.
- A short back-and-forth: ask for a missing detail, wait, then use the answer.

## Example workflow

1. [Chat Trigger](/nodes/builtin/trigger/chat/) receives "Add a task".
2. Respond to Chat: "Which project?", **Wait for the reply**.
3. [Todoist](/nodes/builtin/integration/todoist/) creates the task in `{{ $input.chatInput }}`.
4. Respond to Chat: `Added to {{ $('Respond to Chat').chatInput }}.`

## Common issues

- **The chat shows the agent's text instead**: the reply step is the Respond to Chat step only when the run reaches it. Check that it sits on the path the run takes.
- **Stop in the chat**: stopping keeps the part of the reply already written and marks it as stopped.
