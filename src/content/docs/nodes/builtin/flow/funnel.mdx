Continue as soon as any one of several incoming branches completes.

## What it does

Most nodes wait until every connected branch has finished before they run. Funnel does the opposite: it runs the moment **any one** of its incoming branches reaches it, and passes that branch's data straight through.

If the branch that fired it carried no data, Funnel sends `{ "passed": true }` so the rest of the workflow still runs.

Funnel does not combine data from several branches. To join two datasets, use [Merge](/nodes/builtin/flow/merge/).

## When to use it

- **Several triggers, one shared tail.** A workflow that starts from a [Hotkey](/nodes/builtin/trigger/hotkey/), a [Context Menu](/nodes/builtin/trigger/contextmenu/) and a [Schedule](/nodes/builtin/trigger/schedule/) can send all three into one Funnel, so the actual work is built once. Each run follows only the trigger that fired, and Funnel runs once per run.
- **Parallel branches where any finish is enough.** For example, two branches that each try a different way to get the same data: whichever reaches Funnel first moves the workflow on.

## Example workflow

1. Add a **Hotkey** trigger and a **Context Menu** trigger.
2. Connect both to a **Funnel**.
3. After the Funnel, add [Get Selected Text](/nodes/extension/getselectedtext/) and a [Slack](/nodes/builtin/integration/slack/) node that posts the text.

Pressing the shortcut or using the right-click menu now runs the same two steps.

## Common issues

- **The steps after Funnel run more than once in one run.** Two branches reached the Funnel in the same run, and each one fires it. If you need the steps to run only once after *all* branches finish, connect the branches to the next node directly (nodes wait for every input by default), or join them with [Merge](/nodes/builtin/flow/merge/).
- **The next node gets `{ "passed": true }` instead of data.** The branch that fired Funnel produced no output. Read the data you need from the node that produced it with an expression.
