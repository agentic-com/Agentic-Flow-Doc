A workflow is a chain of nodes: a trigger starts it, and each node does one step. Type what you want to do, such as "click", "pdf" or "summarise", or narrow the list by family, by where the node runs and by what it needs before it works. Each card opens the node's page: its settings, what it sends to the next node, and fixes for common problems.

## How to read a node page

Every node page follows the same order, so you know where to look:

- **Needs a connection**: when the node signs in to a service, a box at the top links to the connection setup.
- **Try it**: a real workflow that uses the node, which you can open in AWFlow.
- **What it does** and **When to use it**.
- **Inputs and settings**: every field as the settings panel shows it. For apps with many operations, pick one to see only its settings.
- **Outputs**: the output ports and the fields the next node receives, with the shape of one item.
- **Dependencies and credentials**: the connection the node uses and the slots where other nodes plug in, such as a chat model for an agent.
- **Example workflow**, **Common issues** (named by what you see), **Recipes with this node** and **Related nodes**.

Nodes that act on web pages or the browser itself run only in the AWFlow browser extension. Their pages say so at the top.
