An AI workflow can look fine on the three examples you tried, then fail on the fourth. **Test runs** run your workflow on a whole list of test cases and score every answer, so you can see the pass rate, and see what changes when you switch model or rewrite a prompt.

(Test runs are sometimes called *evaluations*. A plain **Run** of a workflow is something else: see [Run from the canvas](/app/workflows/executions/run-from-the-canvas/).)

## What you need

1. An [Evaluation Trigger](/nodes/builtin/trigger/evaluation/) in the workflow, holding the test rows: a Data Store list, a Data Store key prefix, pasted CSV, or a Google Sheet (up to 500 rows). You can grow the dataset from real runs: **Add this run's input to the test dataset** on a run in [Runs](/app/workflows/run-history/#add-a-run-to-a-test-dataset). It sits next to the workflow's normal trigger and never starts a normal run.
2. At least one [Evaluation](/nodes/builtin/flow/evaluation/) step set to **Set metrics**, that scores each answer: exact match, contains, similar text, category, tools used, an AI judge from 1 to 5, or your own number.
3. Optional: an Evaluation step set to **Is it an evaluation?** before emails, posts and other side effects, so test runs skip them.

## Run an evaluation

<Steps>

1. Save the workflow. Test runs always run the **saved** version.
2. Open the canvas **⋯** menu › **Test runs**.
3. Press **Run evaluation**. AWFlow runs the workflow once per test row, one after the other. **Stop** ends it early.
4. When it finishes, the run appears in the list with its **pass rate**, the **judge average** (with an AI judge), the **tokens** used and the **typical time** per case.

</Steps>

Open a test run to see each case: its inputs, the outputs you kept with **Set outputs**, and each metric. **Failed** shows only the cases that failed; **Open run** opens the full run of that case in [Runs](/app/workflows/run-history/).

## Compare two test runs

Pick two test runs to **Compare**. You see, per metric, how it changed, and the cases that changed, **regressions first** (cases that passed before and fail now, *Pass → Fail*).

A good routine: run an evaluation, change one thing (the model, the prompt, a setting), save, run it again, compare.

## Good to know

- Test runs are kept **on this device**, the last 20 per workflow. Delete one with its **×**.
- Each case is a real run, marked as an evaluation. Runs hides them unless you turn on **Show evaluation runs**.
- AI judges and AI steps use your models and their tokens, like any run.
