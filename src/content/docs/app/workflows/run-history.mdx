Every time a workflow runs, AWFlow keeps a record of it: when and how it started, how long it took, whether it worked, its log and, depending on the workflow's settings, the data each step received and returned.

**Every run is recorded**: automatic runs (a schedule, a shortcut, a page trigger…), runs you start with **Run**, and single steps you run with **Run step**, even before you save your changes.

## Where to find runs

- **One workflow**: open it and pick the **Runs** tab (next to **Editor** and **Logs**).
- **All workflows**: **Workflows** › **Runs**. It lists the runs of every workflow, plus runs waiting for you and what your agents did, newest first and grouped by day. Filter by **Needs you**, **Failed**, **Running** or **All**, by workflow or agent, and hide manual runs. It opens on **Needs you** when something waits for you.

(Before AWFlow 0.9 the tab was called **Executions**, and the separate **Activity** page is now part of **Workflows › Runs**.)

## Read the list

The chips **All**, **Automatic** and **Manual** above the list show how many runs started each way. Each row shows:

- **Status**: what happened (see below).
- **Started by**: **Automatic · Schedule** (or the trigger that started it), or **Manual** for runs you started yourself, with the step name for a single-step run.
- **Started** and **Duration**.
- **Where**: **Local** (this device) or **Cloud**, the same place the workflow is stored.
- **Metadata**: labels the run attached to itself with the [Run details](/nodes/builtin/core/execution-data/) step, if the workflow uses it.

| Status | Meaning |
| --- | --- |
| **Done** | The run finished without errors. |
| **Done with errors** | It finished, but some items went to a step's [error output](/concepts/flow/error-handling/#send-failed-items-to-an-error-output). |
| **Failed** | A step stopped the run with an error. |
| **Waiting** | The run is paused until you approve something, fill in a form, or a wait ends. |
| **Running** | The run is still going. Its row has **Stop**. |
| **Canceled** | Someone pressed Stop, or canceled a waiting or queued run. |
| **Timed out** | The run took longer than **Longest a run may take** (see [Workflow settings](/app/workflows/settings/#run-limits)), or a step took longer than its **Time limit**, so it stopped. |
| **Interrupted** | The run stopped unexpectedly: the tab, the browser or the extension closed while it was going. |
| **Queued** | The run is waiting to start, because the workflow is set to **Wait in line** or too many runs are going. Its row has **Cancel**. |

A failed run is always **Failed**, never **Canceled**: **Canceled** only means a person stopped it. **Timed out** and **Interrupted** count as failed (they show under the **Failed** chip and in [Insights](/app/insights/)).

### Queued runs

When the workflow is set to **Wait in line** (see [Workflow settings](/app/workflows/settings/#run-limits)), a run that starts while another is going waits as **Queued**: its row says *Waits for the run before it* and its place in line. **Cancel** takes it out of the line.

### One run, across pauses

A run that pauses (an approval, a form, a long Wait) and goes on later stays **one run**: the same row, the same id, its steps and log lines before and after the pause together. The run's header counts its pauses (*2 pauses*).

### Interrupted runs

When the browser or the extension closes in the middle of a run, AWFlow notices it the next time it starts: the run ends as **Interrupted**. Its detail says *This run stopped unexpectedly*, which step was running (*Stopped while running*), the last step that finished, the steps that *Didn't run*, and whether the workflow's error workflow was told (it is, as for any failure of an unattended run). **Debug in editor** is the main button, as on a failed run.

### Timed out runs

A run that goes past a time limit ends as **Timed out**. Its detail names the step that was running (*Get page took longer than its 1 s time limit, so the run stopped*), and **Change** opens where that limit is set. The step shows as **Failed** and the steps after it *Didn't run*. Like a failed run, a Timed out run keeps its step data and offers **Run again**.

**Not synced yet** marks a cloud run that couldn't be saved to your account (offline, or the service was down). It is kept on this device and sent later by itself; **Retry now** sends it at once.

- **Logs** lists the run's lines with their time, level, step (and item) and message: filter them by level (**All levels**), by step (**All steps**) or by words (**Search logs**). Long runs keep the last 5,000 lines; errors and warnings are always kept. In the editor's **Logs** tab, the same run shows as a tree: one row per step with the items in and out and its duration, loop steps as "×24 runs", and under AI steps each model call with its tokens and each tool call. Each call names the building block that made it ("Model call · gpt-4o-mini", the tool, the memory or knowledge base); **Open** in its sheet jumps to that step. Steps that looked at a page show the page drawing (see [Browser control & safety](/app/chat-and-agents/browser-control/#what-you-see-of-a-page)). Search it, or show only **Errors** or **AI**. The plain log is one tap away.
- **Steps** lists each step with the **Input** and **Output** it had in that run, when the workflow saves step data. By default, AWFlow saves step data only for **failed runs**; change it in [Workflow settings](/app/workflows/settings/#run-history) (**Change what's saved** links there). Passwords and keys are never saved.
- **Graph** stays as the last tab.
- A **Timed out** run names the step past its time limit, with **Change** (see [Timed out runs](#timed-out-runs)).
- A run of a version that was deleted since keeps its logs; the graph then says **No workflow snapshot**.

## Debug a run in the editor

**Debug in editor** (the main button on a failed run, also in the row's **⋮** menu) opens the workflow with that run's data on the canvas:

- each step that ran shows its output from that run, with a blue **from run** badge;
- the failed step opens on its error;
- steps you changed since show a **changed** chip; new steps have no data.

A blue banner offers **Run again with this data** (the same trigger data, after a confirmation if steps have side effects), **Open the run** and **Clear**. A step whose earlier steps carry that data says *Input loaded from the 03:02 run · Clear* above its buttons. Fix the failing step, then run it with **Run step**: it uses the data of the run, without running the steps before it again.

The run data is only shown: it is never saved into the workflow, and **Clear** or a full run removes it. If the run used an older version of the workflow, AWFlow asks whether to use its data on the current version or open the version that ran in [History](/app/workflows/history/).

## Run a failed run again

On a failed or canceled run, **Run again ▾** offers:

- **Use the current version**: your workflow as it is now (**Includes your latest saved changes**).
- **Use the version that ran**: exactly what ran then (not available once that version was removed).

Both start from the trigger data the run saved. A confirmation lists the steps that will run again: steps like *Send email* or *Create row* would repeat. To restart from the failed step only, use **Debug in editor**. The new run shows **Retry of 14:02**, and the old one **Retried → Done**.

## Add a run to a test dataset

On a run of a workflow that has an [Evaluation Trigger](/nodes/builtin/trigger/evaluation/), **Add this run's input to the test dataset** adds what started that run as one more test case (in the trigger's Data Store list, created if needed; up to 500 rows). See [Test runs](/app/workflows/test-runs/).

## Fix with Aria

On a failed run (and on a failed step's output), **Fix with Aria** opens Aria on the failure. Before anything is sent, it shows exactly what it will share: the error, the step with its settings (connections become a name only), the shape of the input without its values, and the steps before it. A sample of the data is only included if you switch it on. Aria answers with an explanation and a change you can **Keep** or undo. See [Building workflows in chat](/app/chat-and-agents/building-workflows-in-chat/).

## Runs that need you

When a run pauses for an approval or a form, it shows in a **Needs you** band at the top of **Runs**, and the inbox icon in the header counts it.

- For an approval, click **Approve**, **Reject** or **Cancel**.
- For a form, fill in the fields and click **Submit**, or **Cancel run**.

Canceling records the run as **Canceled**.

### Paused runs continue on the version they started on

If you edit the workflow while a run is paused, the run still **continues on the version it started on**: your changes apply to the next runs. The run's card says so (*You changed this workflow after the run paused*), with **What changed**. If that version was deleted, the run waits for you to choose: **Continue on the current version** (steps that no longer exist are skipped and listed in the run) or **Cancel this run**.

A paused run continues **exactly once**: answering it in two windows, or a Wait alarm firing twice, never runs the rest twice (the second window sees that it was already continued). If the browser closes while it continues, it waits again and can be continued later.

While a run is going, requests to approve an action on a website appear here too; after you approve one, **Approve all remaining** skips the rest of the prompts for that run. Use it with care.

<Aside type="note">
Paused runs are kept on this device until they finish. A [Wait](/nodes/builtin/flow/wait/) of a minute or more in the extension survives closing the tab; in the web app it only lasts while the page stays open.
</Aside>

## Evaluation runs

Runs started by [Test runs](/app/workflows/test-runs/) are hidden from the list. Turn on **Show evaluation runs** to see them.

## How long runs are kept

- **Local workflows** keep their newest **100 runs** each. Older runs are removed automatically.
- **Cloud workflows** keep a number of runs set by your plan, counted across all your cloud workflows. When you reach it, the oldest runs are removed first. See [Plan](/app/settings/plan/).
- Removing old versions of a workflow never removes the runs that used them.
- [Insights](/app/insights/) keep their daily numbers even after runs are removed.
