Every time a workflow runs, AWFlow saves a record of it: when it started, how long it took, whether it worked, and its log. You find these records in the workflow's **Executions** tab.

## Open a workflow's runs

<Steps>

1. Open **Workflows** in the sidebar and click the workflow.

2. Click the **Executions** tab at the top (it reads **Runs** on narrow screens).

</Steps>

The workflow page has three tabs:

- **Editor**: the canvas.
- **Logs**: the live log of the run you started from the editor in this session. It is not kept after you leave.
- **Executions**: every saved run of this workflow.

## Read the list

Each row is one run:

- **Status**: what happened.
- **Started**: when it began, such as *5m ago* or *Yesterday 18:20*.
- **Duration**: how long it took.
- **Where**: *Local* or *Cloud*, the same place the workflow is stored.
- **Metadata**: labels the run attached to itself with the [Execution Data](/nodes/builtin/core/execution-data/) node, if the workflow uses it.

| Status | Meaning |
| --- | --- |
| **Success** | The run finished without errors. |
| **Failed** | A step stopped with an error. |
| **Waiting** | The run is paused until you approve something or fill in a form. |
| **Running** | The run is still going. |
| **Canceled** | Someone canceled the run. |
| **Queued** | The run is waiting to start. |

Failed and waiting runs have a coloured stripe on the left so they stand out.

## Find yesterday's failed run

<Steps>

1. In the **Executions** tab, click **Filter**.

2. Under **Status**, pick **error** (the filter lists the raw status names).

3. Under **Execution date range**, pick yesterday. The last day of the range is fully included.

4. Click the run to open its details.

</Steps>

You can also type in the **Filter...** box. It matches the status name (for example *Failed*), the run id, and metadata such as `order:1234`. Click **Reset** in the filter panel to clear everything.

On narrow screens, use the **All**, **Failed** and **Waiting** chips at the top instead.

## Read a run's details

Click a row, or use **⋮ › Open detail**. A panel opens beside the list with:

- the status, start time, duration, where it ran and its run id,
- the run's metadata,
- a **Graph** tab showing a read-only copy of the workflow **as it was when it ran**, even if you changed it since,
- a **Logs** tab with every log line the run wrote, including the error message that made it fail.

Drag the divider to make the panel wider. **Open in editor** takes you to the current version of the workflow so you can fix it.

<Aside>
The run record keeps the log, not each step's full input and output. To see the data flowing through each step, run the workflow again from the editor and inspect the steps there. Adding log messages or [Execution Data](/nodes/builtin/core/execution-data/) to important steps makes later runs easier to investigate.
</Aside>

There is no "retry" button on a past run. To run it again, use **Run** in the editor or on the workflows list.

## Runs that need you

When a run pauses for an approval or a form, it shows up in a **Needs attention** band at the top of the **Executions** tab.

- For an approval, click **Approve**, **Reject** or **Cancel**.
- For a form, fill in the fields and click **Submit**, or **Cancel run**. Required fields must be filled in.

Canceling records the run as **Canceled**. Only paused runs of the workflow's current version are listed here.

While a run is going, requests to approve an action on a website also appear in this band, with a countdown before they are rejected automatically. After you approve one, **Approve all remaining for this run** skips the rest of the prompts for that run. Use it with care.

<Aside type="note">
Paused runs are kept on this device until they finish. A [Wait](/nodes/builtin/flow/wait/) of a minute or more in the extension survives closing the tab; in the web app it only lasts while the page stays open.
</Aside>

## How long runs are kept

- **Local workflows** keep their newest **100 runs**. Older runs are removed automatically.
- **Cloud workflows** keep a number of runs set by your plan, counted across all your cloud workflows. When you reach it, the oldest runs are removed first. See [Plan](/app/settings/plan/).
