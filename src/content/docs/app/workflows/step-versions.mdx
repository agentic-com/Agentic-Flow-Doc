AWFlow improves its steps over time. When a step changes how it behaves, it gets a new **version**. Steps you already saved **keep the version they were made with**, so your workflows, and the ones you installed from the marketplace, keep doing exactly what they did. New steps you add get the latest version.

## Update available

A step that has a newer version shows an **Update available · v1 → v2** badge on the canvas, and an amber **Update** button in the header of its settings.

1. Open the step and press the **Update** button.
2. The sheet lists what changed in each version and says that your settings are carried over.
3. Press **Update step**. The step is updated in one change: **Undo** (or the toast's **Undo**) puts it back.

Updating is never automatic. Run the step after updating to check its output still suits the next steps.

## Steps with a version 2 in AWFlow 0.9

| Step | What version 2 changes |
| --- | --- |
| [HTTP Request](/nodes/builtin/core/http-request/) | A JSON list in the response becomes one item per entry. **Return** chooses the shape; updating keeps "The whole response as one item". |
| [If](/nodes/builtin/flow/if/), [Filter](/nodes/builtin/flow/filter/), [Route by value](/nodes/builtin/flow/switch/) | One **Match all / any** per group, nested groups, lists and objects compared by content, a **Type check** (Loose or Strict) and **Ignore case**. Your AND/OR rows are converted with the same meaning. |
| [Edit Fields](/nodes/builtin/datatransformation/editfields/) | **Keep other input fields**, dotted names that build nested fields, a JSON mode, and a choice when a value doesn't fit its type. Updating keeps literal names and today's conversions. |
| [Python Code](/nodes/builtin/core/code/) | Runs once for all items by default (much faster); `{{ }}` in the code is no longer replaced; errors name the line and the item. Updating sets **Once for each item**, so the result stays the same. |
| [In-Page Form](/nodes/builtin/flow/in-page-form/) | New field types (email, link, choice, checkboxes, hidden), choices as a list, placeholder, help, default, min/max, and pages with Back and Next. |
| [Chat Trigger](/nodes/builtin/trigger/chat/) | A Chat Memory is no longer required: a [Respond to Chat](/nodes/builtin/flow/respond-to-chat/) step, or the last AI step, is the reply. |
| [Tools Agent](/nodes/builtin/ai/aiagents/toolsagentnode/), [Basic LLM Chain](/nodes/builtin/ai/aiagents/basicllmchainnode/) | With an output parser and a model that can use tools, the answer comes back with typed fields, asked again once if wrong. |
| [Guardrails](/nodes/builtin/ai/aiagents/guardrails/) | Quick checks without a model, **Clean up the text**, and an optional AI policy with a confidence. Updating turns your policy into the AI policy check and leaves the quick checks off. |
| [Merge](/nodes/builtin/flow/merge/) | Three more modes: **Append**, **Combine by position** and **Every combination**. Updating keeps the mode and keys. |
| [Workflow Tool](/nodes/builtin/ai/aidependencies/tools/workflow-tool/) | The agent passes named, typed arguments instead of one text input. |

## A step made with a newer AWFlow

If you open a workflow made with a newer version of AWFlow than yours (an import, or a workflow from another device), a step it doesn't know yet shows a **lock** badge and a card: *made with a newer AWFlow*. It doesn't run, and the workflow is never changed. Press **Check for updates**, or see [Updating AWFlow](/app/updating-awflow/).

## For authors

Publishing doesn't update your steps. Someone who installs your workflow gets the versions you used, so it behaves for them as it did for you. See also [Workflow behaviour versions](/app/workflows/behaviour-versions/), which apply to the whole workflow.
