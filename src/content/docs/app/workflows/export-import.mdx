A workflow is saved as a **`.awf` file**: a small JSON text file with its steps, the links between them, its notes and its settings.

- **Export** a workflow to back it up or share it.
- **Import** a `.awf` file (or a link to one) to use a workflow you downloaded or got from a teammate.

Your connections (keys, tokens, sign-ins) and the values of your [variables](/app/variables/) are never part of the file.

## Export a workflow

<StepCard n={1} title="Open the workflow's menu">
  On the **Workflows** page, click the **⋮** at the start of the workflow's row.

  <StepShot shot="workflow-row-menu" spot="row-menu" n={1} />
</StepCard>

<StepCard n={2} title="Click Export" check="your browser downloads a file named after the workflow, ending in .awf.">
  <StepShot shot="workflow-row-menu" spot="export" n={2} />
</StepCard>

In the editor, the **⋮** at the top right has the same **Export** item. To export many workflows at once, select them in the list and click **Export** in the toolbar at the bottom (see [Bulk actions](/app/workflows/manage-list/#bulk-actions)).

If AWFlow finds a secret typed into a step (an API key pasted in a field, for example), it tells you before downloading and offers to export the workflow **with the secrets removed**.

The file lists the [variables](/app/variables/) the workflow reads (`$vars.NAME`), with their descriptions but **never their values**, so whoever imports it knows what to set.

### Copy and paste steps

To share only a few steps, select them on the canvas and press <kbd>Ctrl</kbd> <kbd>C</kbd> (<kbd>⌘</kbd> <kbd>C</kbd> on a Mac), or **Copy steps** in the menu, then press <kbd>Ctrl</kbd> <kbd>V</kbd> (<kbd>⌘</kbd> <kbd>V</kbd>) in another workflow, even in another window.

- The copy goes through your system clipboard, cleaned first: no connections, no values reset on publish, no secret-looking values ("1 secret-looking value was removed").
- Pasted steps land at the cursor in one undo step. Steps whose names already exist get a new name, and the `$('…')` references to them are fixed. Anything they need shows in **Ready to run**.
- Paste the **text of an `.awf` file** and AWFlow asks: **Paste N steps into this workflow** or **Import as a new workflow**.
- Paste a **link** to a workflow from an allowed site, and AWFlow offers to import it.

## Import a workflow

An import always creates a **new** workflow; it never changes one you already have.

<StepCard n={1} title="Start an import">
  On the **Workflows** page, click **Add Workflow**, pick **Import**, then click **Continue**.

  <StepShot shot="import-source" spot="import" n={1} zoom={44} />
</StepCard>

<StepCard n={2} title="Choose the file or the link">
  Under **From a file**, click **Choose a .awf file** and pick it. Under **From a URL**, paste the link and click **Fetch & validate**. Then click **Continue**.

  <StepShot shot="import-file" spot="choose-file" n={2} zoom={44} />
</StepCard>

<StepCard n={3} title="Name it and create it" check="the imported workflow opens in the editor.">
  The **Name** comes from the file; change it if you like, add a **Description**, then click **Create & open**.

  <StepShot shot="import-details" spot="create-open" n={3} zoom={44} />
</StepCard>

After the import, open **Ready to run**: connect your own accounts (one **Connect** per app connects every step that uses it), set the [variables](/app/variables/) it lists as **Set NAME**, then [run it](/app/workflows/executions/run-from-the-canvas/).

If two steps in the file share a name, the later one is renamed ("HTTP Request 2"); references to the name keep reading the first one, as before.

If the file can't be imported, the message says why in plain words ("Couldn't import: …"): for example the file isn't a workflow (`.awf` or `.json`), or the address didn't return one. A file made with a newer AWFlow, with steps or behaviour this version doesn't know, is refused or shown as *made with a newer AWFlow* (see [Updating AWFlow](/app/updating-awflow/)).

<Aside type="caution" title="Before you share a file">
A `.awf` file has no credentials, but it does hold everything typed into the steps: URLs, page selectors, prompts and any text you entered. Read it through, or open it in AWFlow, before you share it.
</Aside>

<Aside type="note" title="Imported workflows are treated as untrusted">
A workflow you import from a file or URL didn't come from you, so it's treated as
**untrusted code**, exactly like a workflow installed from the marketplace. Before
its steps run, they're **run-gated** against the permissions the workflow actually
needs, and steps that do something sensitive (run code, change the current page,
read or write local files, use a connected app, or reach a new site) ask for your
**consent** the first time. Review and approve those prompts, or choose "Always
allow for this flow", when you're happy with what the workflow does.
</Aside>

## Good habits

- Export important workflows from time to time, and keep the files somewhere safe (a private folder, a team drive or version control).
- After an import, run the workflow once by hand (see [Run from the canvas](/app/workflows/executions/run-from-the-canvas/)) to check it works.
- Before sharing, rename steps clearly and add notes (see [Sticky Notes](/app/workflows/components/sticky-notes/) and [Notes & "How this flow works"](/app/workflows/narration/)) so the next person understands it.
