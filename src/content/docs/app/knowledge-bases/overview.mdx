**In the app:** sidebar › **Knowledge bases**

A **knowledge base** is a set of documents your assistant can search: product manuals, policies, notes, saved web pages. When Aria, an agent or a workflow needs an answer from your documents, it searches the knowledge base and gets back the most relevant **passages** (short pieces of text) to answer from. A **source** is one thing you added: a file, a web page, an open tab, pasted text, or text indexed by a workflow.

3. **Add sources.** Files, web pages, open tabs (extension) or pasted text, indexed on this device.
4. **Test search.** See the passages an agent would get, with their scores, before you rely on them.

## Use it everywhere

| Where | How |
| --- | --- |
| **Chat with Aria** | Click the knowledge bases chip in the composer and pin one or more. Aria searches them and cites the passages. See [Knowledge in chats & agents](/app/chat-and-agents/knowledge/). |
| **An agent, a project or a team** | Pin it in the agent builder's **Knowledge** tab, a project's files, or a team's settings: every chat they take part in uses it. |
| **A workflow** | The [Local Knowledge](/nodes/builtin/ai/aidependencies/vectorstore/localknowledge/) node reads it; the [RAG Agent](/nodes/builtin/ai/aiagents/ragnode/), [Q&A Agent](/nodes/builtin/ai/aiagents/qanode/) and [Tools Agent](/nodes/builtin/ai/aiagents/toolsagentnode/) answer from it; the [Indexer](/nodes/builtin/ai/aiagents/indexernode/) adds to it. |

<Callout type="info" title="Your data" href="/app/knowledge-bases/export-import-backup/" linkLabel="Export a backup">

Documents, passages and their vectors stay **in this browser**. With the default search engine, sources are read and indexed on this device, so nothing is uploaded when you add them. Only a knowledge base built with a **cloud embedding model** sends text to that provider, and a **Device only** base is never shown to a cloud model. Clearing your browser's site data removes your knowledge bases: export the ones you want to keep. The extension and the web app each have their own.

</Callout>

## In short

### Add sources

Open a knowledge base and click **Add sources**: drop files (PDF, TXT, Markdown, CSV, JSON, HTML), list web pages, pick open tabs (extension) or paste text. Each source shows its own status, and indexing keeps going if you close the dialog. Adding a source that is already there updates it in place. [Step by step](/app/knowledge-bases/create/#add-sources).

### Test search

**Test search** shows the ranked passages an agent would get for a question, with a score and a dashed cut-off line at 0.35, and lets you search as a given agent or node. [How to read it](/app/knowledge-bases/test-search/).

### Privacy: Cloud OK or Device only

**Cloud OK** lets passages reach the cloud model that answers. **Device only** shows them to on-device models only: cloud chats skip the base and say so, and workflow nodes stop or answer without it. [Details](/app/knowledge-bases/privacy/).

### Change the search engine (re-embed)

A knowledge base always searches with the embedding model it was built with. **Settings › Search engine › Re-embed with…** moves it to another model; searches keep using the old one until the new copy is complete. [Step by step](/app/knowledge-bases/manage/#change-the-search-engine-re-embed).

## Plans

Knowledge bases are **not limited by your plan**: plans only limit what is stored on our servers, and knowledge bases are stored on your device.
